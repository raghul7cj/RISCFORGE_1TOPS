Execute, memory and write-back stages

How the RISCFORGE core computes results, resolves branches, runs the M extension, talks to data memory and writes results back. For engineers who need to read the RTL or write checks against it.

1. Where these stages sit

EXISTS Execution is split over three modules instantiated in riscv_core/rtl/top.v: execute_cycle (includes the EX/MEM pipeline register), memory_cycle (includes the MEM/WB register and the load/store unit ls_unit) and writeback_cycle (a pure multiplexer). The memory bridge hybrid_mem_interface is not inside memory_cycle: memory_cycle exposes a lsu_mem_* bus (memory_cycle.v:70-77) and the SoC wrapper instantiates the bridge as i_core_data_if (RTL_SOC/riscforge_soc_subsystem.sv:1301). The header comment of memory_cycle.v still lists the bridge and a Data_Memory as children; the code does not.

Hazard handling, forwarding select logic, CSR file and trap commit live in Hazards, CSR and traps. Fetch and decode are in Fetch and decode; a one-page map is in Core overview.

2. Execute stage

EXISTS execute_cycle applies forwarding, runs the ALU, decides branches and jumps, forms the LUI/AUIPC and M-extension results, handles the CSR read-modify-write value, merges exceptions and registers everything into EX/MEM. Figure 1 shows the ALU and branch path; Figure 2 shows how the final result and the EX/MEM register are built.

2.2 EX/MEM register, flush and stall

EXISTS The EX/MEM register has asynchronous active-low reset and then three priorities: FlushM clears every field; otherwise StallM holds every field; otherwise it loads. StallM = wb_redirect ? 0 : mem_stall_i (hazard_unit.v:175) and FlushM = wb_redirect | flush_pipeline_onehot[2] | stallMUL (:199). Because flush beats stall, a multi-cycle M instruction fills EX/MEM with bubbles until the result is ready.

EXISTS Loading a bubble versus a real instruction: when m_valid_out is high, RD_E1 = rd_me and RegWriteE1 = 1 (the M result commits through the normal ALU-result path); when an M instruction is in EX and no result is ready, RegWriteE1 = 0 (execute_cycle.v:329-331). The ID/EX register is also flushed when stallMUL is high (hazard_unit.v:192, flush branch at decode_cycle.v:273), so the M instruction does not stay in EX; the M unit holds the operands itself. OPEN I derived this sequence from the RTL and did not confirm it in a waveform on this page; M-extension verification is the place to look for evidence.

2.3 Exceptions and interrupts raised in EX

EXISTS Priority of the exception packet carried into MEM: (1) local misaligned branch/jump target (cause 0), (2) exception already in the pipeline from fetch/decode, (3) an accepted interrupt, which turns the instruction in EX into a trap packet with cause {1'b1, irq_id_i[4:0]} (execute_cycle.v:459-482). irq_accept_E = valid_E & irq_pending_i & ~new_exc_valid_E & ~exc_valid_E. An accepted interrupt while the M unit is busy aborts it (div_abort_o = irq_accept_E & stallMUL). Cause encoding, CSR update and redirect are on Hazards, CSR and traps.

3. M extension: multiplier and divider

EXISTS Decode flags an instruction as M when opcode is 0110011 and InstrD[31:25] == 0000001 (decode_cycle.v:369). execute_cycle pulses start_M once (guarded by the m_started flag, cleared on m_valid_out or abort) and hands Src_A, Src_B_interim, op_E (funct3) and RD_E to rv32m_unit (execute_cycle.v:300-327).

rv32m_unit splits by funct3[2]: 0 goes to the multiplier rv32m_mul, 1 to the divider rv32m_div. Its stall output is mul_stall | div_stall | valid_in (rv32m_unit.v:85), so the stall is already high in the cycle the instruction starts.

3.1 Multiplier details

  • EXISTS Operands are extended to 33 bits. rs1 is signed for MUL, MULH, MULHSU; rs2 is signed for MUL and MULH only (rv32m_mul.v:45-49). upper is true for every funct3 except 000.
  • EXISTS Booth encoder per 3-bit group: neg = bits[2]; zero when all three bits are equal; two when bits[1] equals bits[0] but differs from bits[2] (booth_enc.v:8-10). Seventeen groups cover the 35-bit padded multiplier.
  • EXISTS pp_gen sign-extends the multiplicand to 66 bits, shifts by 2i (one more when two), and for a negative digit outputs the one's complement inside the shifted window; pp_neg = neg & ~zero becomes a +1 correction at bit 2i. The 17 correction bits are packed into one extra row corr (pp_gen.v:33-38, rv32m_mul.v:103-122).
  • EXISTS CSA levels: 18 to 12 (6 adders), 12 to 8 (4), 8 to 6 (2), 6 to 4 (2), 4 to 3 (1), 3 to 2 (1). The csa module computes bitwise sum and majority; the caller shifts the carry left one place. The module's carry port is 66 bits wide but the instances connect 65-bit nets, so the top carry bit is dropped; only the low 64 bits of the product are used, so this does not affect the result.
  • EXISTS The wrapper holds stall high for the issue cycle plus two more cycles (mul_stall_cnt loaded with 2, rv32m_unit.v:66-83). Counted from the RTL, the stall is high in cycles 0, 1, 2 and valid_out is high in cycle 3, where cycle 0 is the cycle valid_in is high. This is code reading, not a simulation result.
  • OPEN rv32m_mul has no abort input. On an abort the wrapper clears its stall counter, but valid_in already inside the multiplier pipeline is not cancelled (rv32m_unit.v:36-47). Whether a late multiplier result after an interrupt abort is harmless is not shown by the code alone.

3.2 Divider details

  • EXISTS IDLE: on valid_in it stores rd and the operation flags (s_is_div etc.), and sets stall. Division by zero gives all-ones for DIV/DIVU and rs1 for REM/REMU. Signed overflow (rs1 = 0x80000000 and rs2 = 0xFFFFFFFF, signed ops only) gives 0x80000000 for DIV and 0 for REM. Both shortcuts jump straight to DONE. Otherwise the magnitudes are loaded (two's complement negate for signed ops with a negative operand), P is cleared and the dividend sits in quotient (:116-151).
  • EXISTS COMPUTE: cnt counts 0 to 31, so 32 iterations. Each cycle P and quotient shift left as one register pair; P becomes p_shl - D if the shifted value is non-negative, else p_shl + D, and the quotient bit is the inverse of the sign (:94-99, 167-173).
  • EXISTS CORRECT: the quotient register holds signed digits; Q - ~Q converts to binary. If P ended negative, the quotient is decremented and the remainder is P + D. Sign is then applied: quotient negated if the operand signs differ, remainder negated if the dividend was negative (:69-74, 200-203).
  • EXISTS Counted from the state machine: a normal divide spends 1 cycle in IDLE (the start cycle), 32 in COMPUTE, 1 in CORRECT and 1 in DONE, with valid_out high the cycle after DONE; an edge case skips COMPUTE and CORRECT. The count is read from the code, not simulated. stall falls in the same edge that raises valid_out, so the result cycle is not stalled.

5. Hybrid memory interface

EXISTS hybrid_mem_interface decodes mem_addr into three outcomes and routes the request. Figure 6 shows the routing, Figure 7 the handshake state machines and stall formation.

5.1 Handshake and stall rules

  • EXISTS SRAM: the request goes out directly (sram_addr = mem_addr[31:2], mask = byte enables). A read is stalled for exactly one cycle in the IDLE state, then the WAIT state delivers sram_rdata; a write is not stalled (:97-152). The port comments mention a "2-cycle latency" while the in-code comment describes one stall cycle; the state machine shows one.
  • EXISTS AXI write: in IDLE, with a write to the MMIO range, awvalid and wvalid assert together in the same cycle. Next state depends on which of aw_ready, w_ready was seen: both go to WAIT_RESP; only one leaves the other channel pending in WAIT_ADDR or WAIT_DATA, each polling its own ready. WAIT_RESP asserts bready and leaves on b_valid (:157-214). A comment records that the ready checks were once swapped and deadlocked the first MMIO access.
  • EXISTS AXI read: arvalid is high only in IDLE with a read request; IDLE moves to WAIT_READ when ar_ready is seen; WAIT_READ asserts rready and leaves on r_valid (:265-291). AW, W and AR payloads come straight from the LSU bus, relying on the pipeline staying frozen (:344-356).
  • EXISTS Stall: mem_stall = sram_stall_needed | axi_wr_busy | axi_rd_busy, where busy means an active request that has not reached its completing response. So the completing cycle is not stalled and the access retires on that cycle (:375-382).
  • EXISTS Error: mem_err = addr_fault | (write done with non-OKAY resp) | (read done with non-OKAY resp), reported on the completing cycle (:387-389). An address outside both ranges is an immediate fault with no stall.
  • EXISTS Read data: SRAM range returns sram_rdata; otherwise the AXI read data on the release cycle; otherwise the held register (:391-396).
  • OPEN Minimum and maximum MMIO latency depend on the crossbar and peripheral response times, which are outside these files.

6. Write-back

EXISTS writeback_cycle is a four-way multiplexer on ResultSrcW (writeback_cycle.v:34-37). The decoder sets the select: 01 for loads, 10 for JAL and JALR, 11 for SYSTEM (CSR), 00 otherwise (Main_Decoder.v:173-180). M-extension results use the 00 path because the result is injected as ALU_ResultM.
