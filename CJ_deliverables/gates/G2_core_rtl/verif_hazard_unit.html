1. What the unit does

The unit is purely combinational (204 lines). Its inputs come from the pipeline stages and from the WB trap controller; its outputs are two forwarding selects and the stall and flush strobes for each pipeline register. See hazards, CSRs and traps for the architecture description.

FunctionAs implementedSource
ForwardingForwardAE/BE = 2'b10 if RegWriteM and the source register is non-zero and equals RD_M; else 2'b01 for the W stage; else 2'b00. M has priority. Forced to 2'b00 while rst == 0.hazard_unit.v:127-137
Load-uselwstall when ResultSrcE == 01, RdE != 0, and Rs1_D or Rs2_D equals RdE. The compare does not check whether the D instruction really uses rs2.:146-151
CSR stallscsr_stall: a CSR read in D hits an address with a pending write in E, M or W. csr_gpr_stall: ResultSrcE == 11 and D reads RdE. At the instance, csr_write_en_E is wired to csr_valid_E, so any SYSTEM-opcode instruction in E counts as a pending write.:154-167; top.v:622
StallsStallF, StallD = lwstall, csr_stall, csr_gpr_stall, stallMUL or mem_stall. StallE and StallM = mem_stall only. All forced to 0 on wb_redirect. The header comment says StallE also covers M-extension stalls; the code does not.:170-175
FlushesFlushE = (lwstall, csr_gpr_stall, csr_stall each gated by ~mem_stall_i) | PCSrcE | exc_inflight_M | wb_redirect | flush_pipeline_onehot[1] | stallMUL. FlushD, FlushM, FlushW follow.:192-202

2. What must be checked

  • Forwarding correctness. The right source wins (M over W), x0 is never forwarded, and the select is 00 when no match exists.
  • Load-use stall. One bubble when a load in E feeds D; no bubble when the load is not in E; no stall on x0.
  • Branch, jump and trap flush. A taken branch flushes D and E. A WB redirect flushes all four registers and overrides every stall.
  • CSR stalls. A CSR read waits for an older CSR write to the same address; a GPR consumer waits for a CSR result.
  • mem_stall interaction. While mem_stall_i holds the pipeline, no data-hazard bubble may enter E. This is the DEF-001 rule.
  • stallMUL interaction. The M-extension stall freezes F and D and flushes E and M. Its interaction with mem_stall_i is not covered by the DEF-001 fix (scenario H-11).

6. DEF-001 directed regression

Sequence. Taken from the instructions the Stage 3 firmware executes (stage3.dis addresses 0x109c4 to 0x109d0), reduced to its essentials:

        lw   a7, 0(a0)       # MMIO read: mem_stall_i high while the bridge answers
        lw   a5, 736(a2)     # DSRAM load enters EX during the stall
        addi a5, a5, 1       # consumer in ID: lwstall
        sw   a5, 736(a2)     # makes the loaded value observable

Setup. Preload the DSRAM word with a known value K. Set a5 to a different sentinel before the sequence, for example 0xDEADBEEF. A second variant starts with an MMIO store (sw to the MMIO address) instead of the read, since the second occurrence in the disassembly (0x10a0c to 0x10a1c) follows a store.

OutcomeValue stored at the endMeaning
Expected (fixed RTL)K + 1The load executed; a5 was loaded from DSRAM before the add.
Failing (FlushE without the gate)0xDEADBEF0 (sentinel + 1)The load was flushed in EX; a5 kept its old value, as the Stage 3 counters did.

Figure 2 shows the two behaviours cycle by cycle. The cycle positions are illustrative: the real MMIO latency depends on the bridge and is not fixed by the sources read.

Pass criteria for the regression. (1) The final value is K + 1 for read-first and store-first variants, over MMIO latencies of 1 to N cycles and with the consumer using rs1 and, separately, rs2. (2) Mutation check: with the three ~mem_stall_i terms removed from FlushE, the test must fail; this is the "fails on old RTL" condition of ACT-010. (3) The same test is repeated for the other two gated terms: a CSR read (csr_gpr_stall) and a CSR-to-CSR dependency (csr_stall) following the MMIO access. A second person must review the test before DEF-001 can close.
