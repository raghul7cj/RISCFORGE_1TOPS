01 / The path

From peripheral to trap

Pending capture, eligibility and retirement are separate steps. The selected cause and class travel with the interrupt packet; the gateway is acknowledged when that packet commits.

02 / Inputs

Source and cause map

The gateway vector uses bit 0 for cause 7; bits 1 through 12 represent causes 16 through 27. Higher class numbers have higher priority.

CauseSourceClassCapture contract

Event and edge requests coalesce while pending; the gateway is not an event counter. A new captured event wins over a simultaneous acknowledgement. I²C and UART levels depend on the source remaining asserted until serviced. GPIO requires deassertion before a new rising edge.
03 / Decision

Priority and CSR interface

ClassSelectionOrder or rotation
2Fixed7 → 22 → 24 → 26 → 20 → 21 → 23 → 25
1Round robin19 → 18 → 27 → 19
0Round robin17 → 16 → 17

Round-robin search skips inactive or disabled members. Its next preference advances from the committed cause; an uncommitted candidate does not rotate it. Sustained class 2 requests can starve lower classes.

The threshold is software-managed and uses its low two bits. Trap entry and return do not automatically change it. Pending visibility in mip is independent of source enable, global MIE and threshold. MSIP and MEIP can be visible but are not delivered by this arbiter.

Where behavior lives

Trap commit controllerUses the committed packet cause to generate trap and source acknowledgement.
Priority compatibility: SPI EOT retains cause 27 but moved from class 2 to class 1. Its service order and preemption behavior therefore differ from the earlier design; existing firmware and verification infrastructure need review.
Open pipeline risks. An older interrupt-gating CSR write may retire after an IRQ decision used stale state; an IRQ coincident with MUL/DIV stall may interact with packet flushing. These are static-review hypotheses, not confirmed simulation failures. Commit-time recheck with replay is documented as a backup, not implemented behavior.
