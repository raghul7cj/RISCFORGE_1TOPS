3. Gateway capture and clear

ModeSourcesAs-coded behavior
Rising edgeGPIO; bit 1Latch a sampled rising edge; hold until commit acknowledgement. New edge wins over simultaneous clear.
EventTimer / SPI; bits 0, 3, 5–12Capture asserted input each cycle; hold until acknowledgement. Capture wins over clear; repeated events may coalesce.
LevelI2C / UART; bits 2, 4Pending follows input. Gateway acknowledgement does not clear the peripheral condition.
  • Mode constants: edge_mode = 13'h0002; event_mode = 13'h1fe9.
  • Latched inputs must meet clock sampling requirements; sub-cycle pulses are not guaranteed to be captured.
  • Timer compare resets the counter; later matches can generate further events while enabled.
  • Captured edges/events remain pending after the original input drops.
  • A level withdrawn before EX acceptance can cancel the request; withdrawal after acceptance does not undo the trap packet.
  • With MIE left zero in the handler, an uncleared level can retrigger after MRET. Firmware can change that behavior by re-enabling MIE earlier.

4. Winner selection and eligibility

  • Class 2 fixed order: 7 → 22 → 24 → 26 → 20 → 21 → 23 → 25.
  • Class 1 RR: 19, 18, 27. Class 0 RR: 17, 16. Matching committed causes advance RR history.
  • Qualification: pending AND source mie AND global MIE; then choose one winner.
  • Threshold: offer the winner when (winner_class + 1) > mintprio.

5. CSR state, entry and return

  • mintprio exists: 2-bit CSR at 0x7C0; reset 0; upper bits read zero. CSR implementation.
  • Threshold values: 0 permits all classes; 1 permits classes 1/2; 2 permits class 2; 3 blocks all. Trap/MRET leave it unchanged.
  • Global gate: MIE = 0 blocks all IRQ offers. Firmware may re-enable MIE inside a handler.
  • Trap commitment: save PC/cause, set mtval = 0 for IRQ; MPIE ← MIE, MIE ← 0, MPP ← M-mode.
  • MRET: return to aligned mepc; MIE ← MPIE, MPIE ← 1. mintprio stays as software left it.
  • Nesting: one architectural trap-state set; no automatic context stack or depth gate. Software must save/restore context and trap state before permitting nesting.
  • Evidence: unit checks verify threshold behavior and trap/MRET preservation of mintprio; they do not verify a firmware nesting protocol.
  • Handler target: direct mtvec is reachable. A vectored target datapath exists, but the CSR write preserves mode bits; mode 01 is not reachable from reset through ordinary writes.
  • Latency: divider-abort logic exists; no sub-four-cycle entry bound is established.

6. Remaining pipeline / commit checks

Remaining pipeline/commit checks; not completed coverage bins. Their final gate allocation needs agreement.

  • Independent ref: predict eligibility and interrupted PC from stimulus, committed CSR state and instruction order—not the DUT grant.
  • Packet integrity: check cause/PC/class through EX → MEM → WB; exactly one trap commitment and matching acknowledgement.
  • Precision: older instructions finish; interrupted/younger instructions have no forbidden register, CSR or memory effects; correct handler redirect and replay.
  • Negative cases: MIE/mie masks, threshold boundaries, withdrawn level, and pending requests during mask changes.
  • Interactions: memory backpressure, CSR writes in flight, branches, synchronous exceptions, busy MDU, and MRET.
  • Integration: real peripheral stimulus through the gateway to handler completion. Keep unit, core and SoC evidence separate.
