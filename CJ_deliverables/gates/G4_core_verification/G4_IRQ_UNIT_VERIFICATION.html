02 / Testbench structure

Stimulus, checks and coverage

The signature block is tb_irq_restructure. It instantiates irq_gateway, irq_arbiter, wb_trap_mret_commit_controller and csr_regfile as four separate DUT blocks, drives their inputs directly and observes their outputs independently. No core pipeline, fetch/decode stage, peripheral or firmware is present.

The existing SoC IRQ predictor still models the previous hardware nesting stack. It is not used as the oracle in this unit run and should not be treated as validation of the new interface.

03 / Checks

What each unit check establishes

AreaObserved check
ArbiterAll 8,192 pending vectors, four thresholds and six RR pointer combinations, with all source enables and MIE on. Each valid winner and class is compared to the testbench calculation.
GatingEach source is tested individually across threshold, source enable and global MIE. One-hot source masks are also tested with all sources pending at threshold 0.
GatewayPer-source event capture, separated and adjacent events, event/ack coincidence, held events, GPIO edge behavior and level pass-through are checked.
CSRInterrupt-enable bits, pending visibility, threshold transitions and masking, selected trap state and MRET status restoration are checked at the CSR interface.
Commit decoderEach supported committed cause produces its matching one-hot clear; invalid and synchronous cases do not clear a source. This is a block-level decoder check.
RR feedbackMatching committed causes rotate preference; no commit and other-class commits preserve the tested preference.
04 / Review and limits

What is still open

Selective masks

Multiple pending sources with selective enables are not crossed with all thresholds and RR states. This includes lower-priority selection when a higher-priority request is disabled.

Mapping independence

The arbiter reference and RTL share the same cause-to-vector convention. A separately reviewed source map and explicit mapping checks would strengthen the oracle.

Code coverage

Review uncovered items in the IMC report. Arbiter block coverage is 55 of 56; the uncovered item is the committed-cause default branch. Other blocks include functionality outside this IRQ-focused test.

Outside this unit run

Peripheral timing, the connected core pipeline, firmware and nesting are not tested. CSR ordering and MUL/DIV interruption remain separate pipeline hypotheses.

Two independent GPT-6 Luna reviews were read-only. Their valid shared concern was selective-mask coverage; their examples and claims were checked against the testbench before inclusion. No simulation was run by the reviewers.

Historical tb1 diagnostic: a legacy tb1_interrupts.sv run is now retained at legacy_tb1/console.log. It reports 0 of 7 scenarios passing and the same log shows $readmem open failures for the per-test images. The tb1 source encodes older cause, priority and completion expectations, so these historical failures require source/expectation reconciliation; they are not by themselves DUT defects.
