2. The path scoreboard

The claim to be proved, from Verification/step4_checkers/STEP4_SPEC.md section 7.1: every core MMIO access appears as exactly one AXI-Lite transaction and, if the address decodes to an APB rule, exactly one APB transfer on the slot the address map gives, with the same direction, address, data, byte strobes and response, within the timing budgets. This is exactly-once accounting along the chain LSU to AXI to APB.

  • A single record, not a queue. The bridge retires one transaction at a time (axi_lite_to_apb.sv:294-358), so at most one transaction is in flight across it. A single record plus a claimed-by flag is exact. At the LSU tap a second concurrent access would mean the stall mechanism failed; that is detected explicitly as PATH-3013 rather than hidden by a queue.
  • The prediction is read from the RTL. The bridge generates an APB transfer only for a decoded address and either a read or a write with non-zero strobes (axi_lite_to_apb.sv:299). The scoreboard predicts that: a zero-strobe write is a silent OKAY, even to an unmapped address, and an unmapped read is DECERR (STEP4_SPEC.md section 7.3).
  • Second master. The bootloader writes through the same bridge slot 4 without the core. The scoreboard lets it claim the record when the core did not, so its APB[4] traffic is not seen as a ghost transfer.
  • Fifteen checks PATH-3001 to PATH-3015 cover reaching the fabric, one APB transfer per AXI transaction, slot, address alignment, write data, byte strobes at both hops, read data, PSLVERR surviving as SLVERR, direction, latency, the timeout path, one outstanding access, DECERR for the unmapped hole and the zero-strobe no-op. EXISTS
  • Vacuity guard. A suite that observes no MMIO traffic reports CLEAN but is flagged VACUOUS PASS. The rule exists because an earlier bench held the stall high from the first cycle and produced 17 transactions with zero checks (STEP4_SPEC.md section 3.2).

The Step 4 identifiers (PATH-3001..3015) are the implemented set. Rev B uses PATH-0001..0010 for the separate SRAM-path scoreboard (section 8). A written mapping between the Step 4 check list and the Rev B rule inventory was not found. OPEN

5. Timeout and error injection

The framework rule: a path scoreboard compares two observation points, so an injector must corrupt exactly one hop. Corrupting both would show the scoreboard a consistent world (STEP4_SPEC.md section 9.1).

  • Observation-side by default. Injection publishes a corrupted view; the RTL is untouched. This proves the checker logic. EXISTS
  • DUT-side force/release is the only way to prove the real timeout path end to end (a stuck PREADY must make apb_timeout_monitor fire). It is behind +define+STEP4_FORCE_FI and off by default. No retained run uses it. OPEN
  • Wait-state limits. A wait-state injection must exceed the stall bound (64) to trip APB-2004 and stay below the slot timeout (16 cycles for five slots) or the monitor converts it to SLVERR first. For the 16-cycle slots the two constraints conflict, so APB-2004 is exercised only through a slot or bound arrangement that has room between them. How the self-proof resolved this was not checked. OPEN
  • Ordering invariant. The APB monitors must answer before the AXI-Lite monitor (16 or 65536 cycles against 131072). No check asserts this yet (STEP4_SPEC.md section 14.2). OPEN

8. The SRAM-path scoreboard

The MMIO scoreboard starts at the LSU and ends at the bridge, so three paths had no checker: the fetch demux to BootROM and ISRAM, the hybrid interface to the DSRAM direct port, and the privileged-write-only ISRAM AXI port. Rev B 8.4 adds a scoreboard with four scored properties: transaction accounting, route exclusivity, arbitration, and write protection. It reuses the PATH-NNNN family. It is a specification only; no RTL of it was found in the repository. SPECIFIED
