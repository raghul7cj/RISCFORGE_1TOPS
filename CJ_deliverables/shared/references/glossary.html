1. Evidence status labels

LabelMeaning
EXISTSPresent in the repository and read by the author of the page; usually cited to a file and line.
SPECIFIEDStated by the Rev B plan as the intended state. Nothing is built or executed. Rev B itself says no phase has been executed.
OPENUnknown, disputed or not yet decided.
ASSUMED / TBDRev B planning values. ASSUMED(D-xx) is an estimate with a stated basis; TBD(D-xx) is a value nobody has supplied yet (for example team size, D-GR03).
PASS (matrix)A retained run passed for the stated boundary only. It is not a percentage of requirements covered and does not by itself close a Rev B check ID.
untestedA gate or check that could not be evaluated. Rev B treats it as not a pass.

3. Gates and phase conditions

ItemMeaning
G0Harness integrity (per run): canonical module set matches, tool version pinned, artefact write test passes.
G1Stimulus reached the DUT (per run): instructions retired, AXI transfers, APB transfers and attestation words all greater than zero.
G2Checker viability (per candidate): every bound check ID can be shown capable of reporting.
G3Checkers all pass (per run): no open findings, no unexplained ring drops, scoreboards drained.
G4Coverage closed (per candidate): every declared bin hit, waived or excluded with a record.
G5Compliance and formal closed (release): stamped once, in P6.
G6Traceability complete (per candidate): no orphan requirement, check, test or defect.
Phase-entry conditionA predicate over evidence that must hold before a phase may start. Not a gate and never stamped (Rev B Table 21.1).
CT-1 to CT-5Core-trust conditions: compliance, lock-step, core assertion viability, core formal goals, boot entry. Entry condition for P2 onward.
DC-1, DC-2Decision cutoffs: scope at the exit of P0, behaviour at the exit of P2. An undecided item defaults and is logged as defaulted.
Track FThe formal track. Runs in parallel with phases and stamps no gate.
CFG-C, CFG-SCompliance configurations: core-only wrapper (exists) and SoC context (specified).

4. Run identity and change classes

ItemMeaning
H_rtl, H_filelistSHA-256 of the 105-line manifest built from the non-comment entries of RTL_SOC/soc_subsystem.f, and of the relativised filelist (Table 21.10).
ID-1Module-name uniqueness: no divergent duplicate module reachable from a filelist that also names a testbench.
ID-2Every filelist entry in scope resolves.
ID-3No absolute paths in filelists in scope.
Freeze point FDeclared at the exit of P1b. RTL may still change, but every edit carries a change note and no gate verdict transfers across an identity change.
Class A / B / C / D / XChange classes for the re-run matrix: core, fabric/reset/boot, peripheral, harness only, tree hygiene (Table 21.12).
SD-1 to SD-10Separation-of-duty predicates, for example closer is not the fixer, release signatories are distinct.
