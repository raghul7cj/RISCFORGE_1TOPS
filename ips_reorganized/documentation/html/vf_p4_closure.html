P4 Closure

P4 turns the checks built in P2 and P3 into candidate-level evidence: a coverage model, proof that each checker can report, a generated traceability matrix, a frozen candidate regression and a compliance re-run. Its exit stamps the three per-candidate gates G2, G4 and G6.

1. Objective and sub-phase flow

The three per-candidate gates cannot be decided per commit; they consume artefacts that accumulate across a candidate's runs (Rev B Table 6.1). P4 builds those artefacts in a fixed order. Bins need checks to exist (P4.1). A viability record belongs to a bound check (P4.2). The traceability matrix would count every check as an orphan if it were generated before the ledger is populated (P4.3). A candidate cannot be frozen before G2 and G6 are decidable (P4.4). Compliance is re-run at the frozen identity (P4.5). Figure 1 shows the flow.

5. Check families and rules

IDRule (Rev B Table 10.5)
CR-1A bin closes only when its owning family records a hit; an assertion bin additionally needs a non-vacuous check. "Evaluated" alone never closes it.
CR-2A waiver records that a bin is unreachable and why; it never replaces a hit.
CR-3Every waiver has owner, justification, review date; the requester is not the approver.
CR-4Coverage is reported per run and merged per candidate at one RTL identity; a regression in any bin between candidates is a failure.
CR-5"Coverage is high" is not a closure criterion; no combined score is built.

Compliance: 69 applicable tests (38 I, 8 M, 7 Zicsr, 16 privilege) of 162 in the tree; 93 out of scope (27 C, 1 Zifencei, 65 K), each recorded with a reason (Rev B Table 6.4). The denominator is 69, never 162. Traceability: six links (requirement, design element, check ID, test, evidence, result), and Rev B notes that six seed requirements carry no check ID, so G6 fails at Rev B.

9. Execution proposal

Proposal, not Rev B text. The stage 6 brief defines learning-project closure; the steps below start there and keep the full Rev B gates as the stated target.

  1. Manifest first. Enumerate existing smoke, core, MMIO, register/device, reset, interrupt and fabric tests with scenario, configuration, identity, seed, command, verdict and artefact location, using the existing runner.
  2. P4.1. Declare bins per owning family with the functional matrix (address/device, access type, response, reset type, interrupt masked/taken, trap type). Use native simulator coverage if the tool of record supports it (ACT-006); otherwise event counters, with no invented percentages.
  3. P4.2. For each important checker, retain one watched-condition-occurred record and one deliberate negative case, kept distinct from normal DUT regression.
  4. P4.3. Generate requirement to test to result for the selected milestone with UNKNOWN or NOT RUN entries visible; do not hand-maintain.
  5. P4.4. Hash the identity, stamp ID-1 to ID-3, freeze, and run the manifest without RTL change; save failing commands and seeds.
  6. P4.5. Run the 69 applicable tests at the same identity and report separately from the SoC regression.
  7. Report. HIT / NOT HIT / NOT APPLICABLE / UNKNOWN with reasons, plus p4_findings.md. Make no full sign-off claim.

Not claimed. A learning-project baseline is not G2, G4 or G6.
