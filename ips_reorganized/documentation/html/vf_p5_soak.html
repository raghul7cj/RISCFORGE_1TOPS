P5 Campaign convergence and soak

P5 runs the frozen candidate until the convergence rules of Rev B Table 6.5 are met: seeds saturate, reset and boot scenarios are all hit, cold-boot cycling and soak are accumulated, and each of the 7 timeout monitors has been seen to expire. It stamps no gate; it supplies the evidence that G4 and G5 consume.

1. Objective and convergence

Table 6.5 states rules, not volumes, and a rule cannot be evaluated without a campaign to evaluate it on. Rev B therefore inserts P5, in which those rules are run to convergence on the frozen candidate. A stimulus count with no derivation is an opinion, so each stream carries a derivation rule and a convergence criterion; where the number is not yet derivable it is TBD(D-025), and the rule still binds. Provisional floors are 20 nightly seeds, 1000 cold-boot cycles and a 24-hour soak, tagged ASSUMED(D-024).

Seed rule: N_seeds is the smallest N for which (1) saturation holds, meaning the last seed added produced no first-hit on any bin, and (2) stability holds, meaning that over K consecutive partitions the seeds hit every bin in the convergence set with at least H distinct seeds each. Constants: H = 2, K = 3. If either clause fails, N grows by the partition's own seed count and the partition repeats (Figure 1).

3. Exit criteria and gates

Rev B Table 20.1: G2, G4 and G6 re-evaluated on the soaked manifest; the soak and cold-boot campaign converged per Table 6.5; track F closed as an input to G5. G5 is not stamped. Rev B Table 21.3 lists "none" as the gate verdict stamped at P5 and says it feeds G4 and G5. Read together: P5 produces evidence and re-evaluates the per-candidate gates; it stamps no new gate verdict. P5 is the last phase before P6, and there is no path to G5 that bypasses it, so it can only be compressed by running more partitions in parallel, which is a capacity decision.

5. Check families and timeout monitors

P5 adds no new check family. It accumulates hits for bins and checks defined earlier (RS, IC, FP, PC, CR). The monitor criterion draws on FP-10 (Rev B Table 14.3): each timeout monitor fires at its configured threshold and recovers, the fired slot is blocked afterwards and the sticky bit sets without raising any interrupt.

9. Execution proposal

Proposal, not Rev B text. The stage 7 brief defines a reduced, bounded milestone: Rev B floors are not automatically required for it.

  1. Take the Stage 6 manifest and one frozen identity. Log tool and environment differences; any RTL edit starts a new candidate.
  2. Build one bounded command that repeats representative boot, MMIO, device, interrupt and error scenarios; add a seed sweep only where random stimulus already exists.
  3. Stress observable boundaries. Cold versus warm boot, reset during one transaction, legal bus wait variation, one controlled timeout or error; check progress, response correctness, drain of outstanding transactions and recovery.
  4. Measure convergence per batch. Track new bin hits, repeated failure signatures, timeout counts, non-deterministic outcomes. Expand seeds only where important bins or instability remain.
  5. Triage before changing anything. Reduce each failure to its first discriminating test, keep seed and log, classify as DUT, checker, simulator or unresolved.
  6. Report in convergence_summary.md the exact run counts, coverage progression, failure index and the Rev B floors that were not executed. Then, only for the full plan, scale to the Table 6.5 rules: 20 nightly seeds with H and K, 1000 cold boots, 24 hours, and all 7 monitors expiring.

Not claimed. No soak, cold-boot-cycling or monitor-expiry result exists. A reduced campaign is not P5 exit.
