1. Objective and position

Rev A made formal a phase after closure, which produced an unsatisfiable graph (decision D-23). Rev B removes formal from the phase scale: it is a track entered at the exit of P1a and required to close before P5 starts. If it were numbered as a phase it would acquire a predecessor and a successor by construction, which is the defect being removed. Figure 2 shows where the track sits against the phases; Figure 1 shows its internal milestones.

The track is on the critical path for exactly one edge: track F exit to P5. Starting it at P1a gives it the whole of P1b, P2, P3 and P4 as slack; starting it later removes that slack (Rev B 21.5).

2. Entry criteria

Rev B Table 21.4: the P1a exit for the core goals. Peripheral and fabric goals enter incrementally at the P1b and P2 exits. The track does not wait for P3 or P4 and neither waits for it. The core property register may be encoded only against a core whose compliance and lock-step results are in hand, so a failing property is unambiguous.

OPEN Rev B is not consistent on the device entry point: Table 21.4 and the intro of 18 say P1b and P2 exits, decision D-GR05 says the P2 exit for device goals, and the tracker records "F entry points disagree" as erratum DEF-011. This page follows Table 21.4.

9. Execution proposal

Proposal, not Rev B text. The formal track brief selects a narrow subset and is independent of the simulation phases.

  1. Discover the tool. Identify the formal engine, language subset and simplest synthesizable target. If none, record BLOCKED and move the properties into simulation as assertions.
  2. Pick two or three local invariants. Suggested by the brief and by Rev B criticality: sram_mux grant and rvalid history (FRM-0010, FRM-0011), a gateway/arbiter gating claim (FRM-0004 to FRM-0007), or a reset/trap transition invariant. State assumptions and bounds explicitly.
  3. Cover first. Add an antecedent cover or negative control per property before any proof run (FAB-1).
  4. Run and classify. Report PROVED, FAILED, INCONCLUSIVE or BLOCKED from logs. Classify each counterexample as RTL defect, bad assumption, wrong property or inconclusive; keep the minimal waveform.
  5. Relate to simulation. Add a directed reproducer for one counterexample, or use one assertion in the P3 regression. This is how a result changes the test plan.
  6. Widen to the register. Encode the critical groups from the core outward, record vacuity, triage, freeze, and publish counts per module in formal_findings.md.

Not claimed. A small proved subset is not track F closure. Compilation of an assertion is not a proof.
