1. Scope and status

This page covers ls_unit (byte enables, store alignment, load extension), the misalignment and access-fault logic in memory_cycle.v, and hybrid_mem_interface (SRAM versus AXI4-Lite MMIO routing, handshakes, stalls, errors). Status: EXISTS none of these three has a dedicated unit testbench. Indirect evidence is limited to the RISCOF load/store alignment tests (older RTL), an interrupt testbench that uses the SRAM path with the AXI side tied off, and a structural LSU-to-AXI-to-APB monitor run in a stub harness. Rev B specifies much more (CP-8, MMIO exactly-once) and none of that is built.

Live defect. DEF-001, a load-use flush inserted during an MMIO memory stall that dropped loads, is fixed in hazard_unit.v (FlushE gated by ~mem_stall_i, hazard_unit.v:192) but its status in Verification/status/defects.csv is FIXED-UNVERIFIED: no regression test proves it. Test LM-12 below is that regression.

Because LH and LHU look only at addr[1], they would silently read the wrong half on an odd address; they rely on the misalignment check below to stop the access first.

2.3 Misaligned access as implemented

EXISTS memory_cycle.v:115-147,177-193. LW and SW trap if addr[1:0] is not 00; LH, LHU and SH trap if addr[0] is 1. Byte accesses never trap. The cause is 4 (load misaligned) or 6 (store misaligned), mtval source is the full address (ALU_ResultM), and the memory request is suppressed (lsu_mem_req is gated by the misalignment and by an earlier exception), so no side effect leaves the core. The misaligned stall is masked so the exception is captured instead of the pipeline holding (memory_cycle.v:186-193). An earlier exception propagating from a previous stage wins over a new one (:144-147). The misaligned cause takes priority over an access fault when both occur (:134-139). The core therefore traps on misaligned data access; it does not emulate it in hardware.

3. Bus error to access fault (Rev B 8.5, CP-8)

SPECIFIED Rev B 8.5 defines six error sources, ERR-1 to ERR-6, that all collapse to one signal, and seven negative cases N1 to N7. The core must take cause 5 (load) or 7 (store), mepc = faulting instruction, mtval = the data address, no shadow-stack push, and the faulting instruction must not retire (Rev B Tables 8.6 to 8.8). The RTL side is EXISTS: mem_err is built as in Section 2.4, memory_cycle.v:132-139 turns lsu_core_err plus access type into cause 5 or 7, and tval is the address. Rev B grades ERR-1 to ERR-5 and N1 to N6 in the full-SoC configuration and ERR-6 and N7 only in a fabric-only configuration, because the core cannot reach those addresses. No CP-8 check is built. The decode-hole and timeout cases (ERR-1, ERR-3, ERR-4) live outside this unit (bridge, bus monitors) but end at mem_err, which is where this page's checks begin.

4. Exactly-once MMIO effect across an interrupt (Rev B 16.10)

SPECIFIED Rev B finding 30 requires that an MMIO write with a visible effect happens once even if an interrupt arrives at the worst moment. Four scenarios are named: a UART transmit write (count characters), a GPIO toggle write (parity of the output), an I2C start command (count START conditions) and a Timer 0 compare write (count interrupt acceptances). Injection points run from the store in EX, through MEM with the request already driven, to WB and one cycle after the APB handshake. Two oracles are both required: the instruction-set simulator's access stream versus the DUT's LSU stream, and a per-peripheral effect counter. EXISTS on the RTL side: while mem_stall holds the store in MEM the AXI request is held and stable (Section 2.4), which is the property that makes exactly-once plausible; the interaction with an accepted interrupt (flush of earlier stages, retirement of the stalled store) is not examined by any retained test. Neither oracle is built, and the reference ISS flow is planned in later phases (see the lock-step page).

5. Check architecture

The harness is built in two layers. The first drives ls_unit and hybrid_mem_interface directly on the LSU bus, which makes every row of the truth tables in Sections 2.1 and 2.2 cheap to cover exhaustively (3 sizes x 4 offsets x data patterns). The second runs instruction sequences through the full core so that memory_cycle exception logic, the hazard unit and the write-back path are in the loop; it reuses the lock-step comparison planned for the core.

8. What this page does not claim

  • The waveform in Figure 3 and every expected value are derived from the source and the Rev B text, not from a simulation.
  • It does not claim misaligned handling meets the privileged specification in every detail; it describes what the RTL does.
  • It does not describe the crossbar, bridge or peripheral registers; those are verified on the fabric pages.
