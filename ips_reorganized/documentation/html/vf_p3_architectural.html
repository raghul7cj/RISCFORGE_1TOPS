P3 Architectural checks

P3 verifies behaviour that no register read-back can show: reset and clock ordering (P3.1), interrupt delivery (P3.2), fabric and bridge response (P3.3), and the integration of the firmware oracle (P3.4). This page gives the entry, exit, check families and a concrete order of work for the four sub-phases.

1. Objective and sub-phase structure

P3 is decomposed into four sub-phases. Three start from the P1b exit and are independent of each other. P3.1 is also independent of P2. P3.4 alone waits for P2, because the firmware oracle observes device behaviour and there is nothing to observe until the device models exist. All four rejoin at P4.1 (Figure 1). A sub-phase identifier is never used without its parent, and the gate stamped at P3 exit is the conjunction of the four sub-phase exits.

9. Execution proposal

Proposal, not Rev B text. The stage 5 brief defines a representative subset (one scenario per area); the order below runs that subset first, then fills the families.

  1. P3.1 first, one scenario at a time. Capture current release order; run RS-1 (cold) and RS-2 (warm) with a self-checking firmware outcome; then RS-4 (reset during one APB access). Preserve traces. Expect RS-11 to fail and register that as the expected result.
  2. P3.3 in parallel. Pick one negative bus condition (unmapped address to FP-5, DECERR with no target activity); confirm one accepted request, one response, no duplicate completion, and the CPU access-fault behaviour only if architecturally expected. Then FP-6 and FP-10 timeout abort on one slot.
  3. P3.2 with one routed source. Confirm real wiring first (Table 13.1, top.v:207,548). Suggested candidate to confirm: Timer 0 channel 0 compare reaching mip[7]. Check enable, pending, trap entry, mepc, mcause, mstatus, handler, MRET, plus one masked-interrupt negative case (IC-14 style). Do not count unrouted timer lines or the AON watchdog.
  4. P3.4 after P2 exit. Make one firmware test check a device effect and cross-check against the passive model (Figure 2); then force a disagreement and show an attributed FAIL.
  5. Fill families. Extend to RS-3 sweep, RS-12/13, the IC gate matrix and nesting cases, FP-1 to FP-11, marking non-executable rows explicitly.
  6. Record findings (p3_findings.md): outcomes, missing source wiring, untested families. Do not soften predicates or edit RTL silently.

Not claimed. Finishing the representative subset is not P3 exit. Exhaustive reset-domain crossing, all-source nesting and the full boot-FSM sweep remain open Rev B obligations.
