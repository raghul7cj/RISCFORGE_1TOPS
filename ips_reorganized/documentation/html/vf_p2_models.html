P2 Model completion

P2 turns the SoC bus-path result of P1b into device-level evidence: a register model for each of the six APB peripherals, an independent second oracle per device, and a cross-check of the firmware's own report. This page states what P2 must achieve under Rev B, what blocks it, and a concrete order of work.

1. Objective and position

P1b proves that a software access reaches the right APB window and that every finding goes through one reporter. It does not prove that the peripheral returns the right value. P2 closes that gap. Rev B 21.3 gives the content as: a full register model for all 6 APB instances, device VIPs reachable from every harness, and an attestation cross-check.

The design contains six integrated APB instances (NUM_APB_SLAVES = 6, Rev B 15) and 55 declared register identities, 54 of them reachable (UART SCR at offset 0x1C is declared but not implemented). Rev B counts 275 register-model clauses (55 identities x 5 access modes). The AON watchdog is real RTL but is not integrated and is excluded from P2.

Rev B 15.1 draws a scope line that shapes P2. The SoC-level plan verifies connectivity and end-to-end flows. Device internals (state machines, framing, bit timing) are inherited from each IP's own regression and are not rebuilt. The "device VIP" of Rev B 21.3 therefore means the observation points needed for the second oracle (pin or timing), not a new full device simulation. Figure 1 shows the three oracles and the attestation cross-check around one harness shape.

7. Effort and risks

Effort. 25 to 45 engineer-days, SPECIFIED as ASSUMED(D-GR01) in Rev B Table 21.3. This is the widest phase in the register. No throughput has been measured: the per-check and per-scenario costs are TBD(D-GR01) and will be recomputed at the exits of P0 and P1a. 9. Execution proposal

This section is a proposal, not Rev B text. The stage 4 brief defines a reduced learning milestone that is a strict subset of full P2. The proposal runs the reduced milestone first, then widens.

  1. Gate the start. Confirm P1b exit and CT-1 to CT-5 at a recorded identity; generate or hand-build the register header; record DC-1.
  2. Reduced milestone (stage 4 brief), GPIO first. Reuse the P1b monitor transactions. Build W1 and the GPIO model with an independent expected-state table. Run a directed table: reset read, write and read-back, byte strobe, reserved or invalid address, one W1C case. State the PSLVERR expectation per row from Rev B Table 15.5, not from the DUT.
  3. Prove the oracle can fail. Corrupt one model expectation, observe an attributed FAIL, and retain the log. Label every unfinished device NOT TESTED. Write p2_findings.md.
  4. Add the second oracle type. Timer 0 with the cycle-accurate timing oracle (tolerance 0), so both oracle kinds are shown working before widening.
  5. Widen in volume order. SPI, UART, I2C, Timer 1; then W7 sweep and error-policy rows; then W8 attestation; then W9 DC-2 record.
  6. Close the loop. Evaluate PC-1 to PC-6 per instance, list every untested item with its missing mechanism, and stamp G3 on the P2 partition.

Not claimed. Completing the reduced milestone does not satisfy P2. Full P2 stays open until all six instances have all three oracles green.
