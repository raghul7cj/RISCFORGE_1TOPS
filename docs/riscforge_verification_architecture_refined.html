HOW TO READ THE THREE PATHS
CFG-C — architectural compliance

Core-only test wrapper. Produces ISA compliance evidence; it cannot establish SoC bus-error, peripheral or deployed interrupt behaviour. 69 applicable cases are the target, not an executed pass count.

CFG-F — fabric stress

Bus-functional models replace both bus masters and the targets. This exposes arbitration, contention and SRAM control that are not reachable in the integrated SoC configuration.

CFG-S — shipped integration

Boot, SRAM, reset release, peripherals, firmware and interrupts coexist. Traces, mailbox, pins and bus observations support configuration-valid checking. ISS lock-step remains specified.

Status and independence rule. The source plan explicitly says no check in the plan has been executed. “SPECIFIED” means required but not implemented; “TBD” identifies an unresolved decision. A checker must use an independent oracle and demonstrate viability, not merely remain silent. Configuration validity is defined by Rev B Table 16.2, not by the diagram's apparent proximity.

How the infrastructure hangs together

Three ideas organise it. Independence: every checker and model names an artefact or external specification it was not derived from, and the author of a check may not be the author of the RTL it judges. Anti-vacuity: a check must be shown able to fail before its silence counts as evidence. Identity: every result is tied to a recorded RTL hash, filelist hash, tool version, seed and plusargs, so a log missing any of them is not evidence.

Work is described in two orthogonal ways that must not be mixed. A band says what kind of work it is (stimulus, observe, check, close), and a layer (L1–L7) says where in the design it applies. The diagram's columns are the bands. The check column is split by layer.

Stimulus BAND-1 · what drives the DUT

Firmware suites + BSP L7

Self-checking firmware that writes attestation words into a mailbox in DSRAM. The harness reads them as the firmware-level oracle, and G1 needs at least one per partition. The CFG-S image length is a compile-time constant of 64 instruction words and 0 data words (D-052), which most random streams and C suites exceed unless it is raised.

Constrained-random + directed

Random stream volume follows the convergence rule in Table 6.5, so the number of seeds is derived rather than chosen. Volumes for the directed, reset, fault and interrupt scenarios are TBD(D-025): the rules are binding, the numbers are not.

RISCOF compliance suite

69 applicable tests out of 162 in the vendored tree (38 I, 8 M, 7 Zicsr, 16 privilege). The other 93 are out of scope, each with a recorded reason. It runs against the core-only configuration on Icarus Verilog.

BFMs and device VIPs

Master-side and target-side bus-functional models with configurable waits and responses drive the fabric configuration. External slave models exist for I2C and SPI, plus an SPI NOR flash model for boot.

Fault injection INJ-1…4

Four mechanisms: bind, force, model mutation and an injection port. They produce 17 derived fault cases and are how checkers get their negative cases. INJ-1 needs a simulator that can bind, so it runs only on VCS. Any hierarchical force must appear in the run manifest or the result is irreproducible.

Fast-boot backdoor

A testbench deposit of the image straight into SRAM, skipping the SPI boot path (§12.9). Eligibility is declared per check, and equivalence obligations apply so the backdoor cannot hide a boot defect.

Every check family is marked VALID, PARTIAL or INVALID per configuration in Table 16.2, and a check must not be reported green where its stimulus cannot be produced. For example IC-1…IC-9 are INVALID in CFG-C because that core tree has a different, fixed-priority interrupt design. Observation BAND-2 · how the environment sees the DUT

Observation points CP-1…CP-12

Twelve attachment points on the MMIO and SRAM paths where required checks sit (Table 8.2). A per-slot observation tap on the SoC MMIO path is fixed in phase P1b.

Bus and timeout monitors

Six timeout monitors on the APB slots and one on the core's AXI-Lite master, all in sys_rst_n. The bootloader's own AXI master is unmetered. P5 requires all seven to be observed expiring.

Retire trace SPECIFIED

The record of committed instructions that lock-step consumes. Its port (ISS-14) is required but not built, so the testbench extracts retirement hierarchically in the meantime.

Pin-level monitors

For UART, GPIO and both timers there is no external slave model, only a monitor against the port contract. The plan records this as an open limitation of layer L4.

Mailbox + attestation

Words the firmware writes to DSRAM through the BSP mailbox, read by the harness. Intent must trace to a record that is not the test itself.

Reset and boot observation

Reset release order, the 16-state boot FSM, and the timeout expiries feed the reset properties (RP-n) and boot checks (BOOT-nn, plus the specified integrity rows BOOT-S1…S6 and negative cases BOOT-N1…N9).

Formal track F TBD(D-038)

Runs in parallel rather than as a phase: a property register with covers, bounded-liveness encodings, proof runs and vacuity records. Eleven FRM properties are registered for the fabric and interrupt interface (Table 18.1). The tool of record is not yet established, and it feeds G5 rather than being a gate itself.

Check population

432 checks plus a to-be-determined remainder (Table 9.6). Families include FP-1…11 (fabric), IC-1…24 (interrupts), ISS-n (lock-step), BOOT-nn, RP-n, CDC-nnnn, PC-1…9 (peripheral sign-off) and DEV-nnnn (per-device). Each check carries a status such as EXECUTABLE, MUST-FAIL, SPECIFIED-ONLY, NEGATIVE-PROOF, BLOCKED, VACUITY-SELFTEST or FORCE-REQUIRED (Table A.3).

Closure BAND-4 · turning evidence into a verdict

Coverage VCS U-2023.03

Four families that never substitute for each other: code (line, branch, condition, toggle over the generated filelist), structural (FSM states, decode regions, arbitration outcomes, timeout bins), functional (declared cross-instance bins) and assertion (a check ID that is evaluated and non-vacuous). Reported per run and merged per candidate at one RTL identity. "Coverage is high" is not a closure criterion and no combined score exists (CR-5).

Viability ledger

The evidence a check can report: negative_case_pass or vacuity_proved. A check that was evaluated (antecedent satisfied) but has no viability record is vacuous. G2 asks whether the checker can report; G4 asks whether the behaviour was observed.

Failure reporter + triage

The single harness path every finding passes through. The triage owner assigns, within one working day, a primary owner, class and severity. Severity is set at triage, never at closure and never by the fixer.

Traceability matrix

Six links from requirement to defect, generated rather than typed. G6 fails on any orphan requirement, check, test or defect, and every defect must link to a regression test.

Waivers

A waiver records unreachability and never substitutes for a hit. It needs an owner, justification and review date, and the requester and approver differ. It returns to review when it expires, when the RTL identity changes, or when the masked defect is re-filed.

Run identity and RTL identity

Each run records eight fields: RTL hash, filelist hash, tool and version, plusargs, seed, scenario identifier, verdict and artefact locator. Reproducibility (QG-10) measures the four that affect reproduction. The repository has no git history, so identity is a hash recipe (Table 21.10):

  1. Take the 105 non-comment entries of RTL_SOC/soc_subsystem.f (a filelist, not a directory walk).
  2. Resolve every entry. Any unresolved entry means no hash, and the run is untested.
  3. Rewrite paths to repository-relative POSIX form and SHA-256 each file's raw bytes.
  4. Build a sorted manifest. Its SHA-256 is H_rtl; the hash of the relativised filelist is H_filelist.
  5. Stamp every header with three identity checks: ID-1 no divergent duplicate module names reachable from a testbench filelist, ID-2 no unresolved filelist entries, ID-3 no absolute paths.

Table 5.2 describes the hash more loosely (filelist plus four anchor files). Use Table 21.10 as the recipe. Two different timer.sv files exist and different filelists compile each, which is why ID-1 treats a divergent duplicate as an identity failure.

Ten separation-of-duty rules (SD-1…SD-10) back this, for example check author ≠ RTL author (SD-1), waiver requester ≠ approver (SD-2), and three distinct sign-off signatories (SD-8). Where a small team cannot separate a block, the escape is a recorded waiver, not silence.

Severity

S1 release-blocking, not waivable, needs a linked regression test and a second signature to close. S2 major, blocks the dependent phase exit, waivable only with a review date within one release cycle. S3 minor, close or waive before the release in which it was filed. S4 observability, no effect on any gate. S5 observation, trend only.

Defect class: where the fault lies

C-DUT RTL wrong. C-TB checker, VIP, monitor or model wrong. C-HARNESS filelist, generator, CI or run-identity recording wrong. C-SPEC specification ambiguous or contradicted, closed by a decision rather than a code change. C-ENV tool, licence or environment. C-EXPECT expected value wrong while DUT and specification are right.
