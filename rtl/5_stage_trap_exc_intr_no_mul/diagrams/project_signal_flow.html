Exception Trap Flow

Shows the end-to-end exception path from detection through pipeline propagation, WB commit, CSR writing, and PC redirect.

sequenceDiagram autonumber participant IF as IF participant ID as ID participant EX as EX participant MEM as MEM participant WB as WB Commit participant CSR as csr_regfile participant PC as PC Mux participant HZ as hazard_unit Note over ID,WB: exception metadata travels with the instruction ID->>EX: exc_valid, exc_cause, exc_tval, exc_pc EX->>MEM: preserve exception sideband MEM->>WB: preserve sideband to WB loop exception in flight WB->>HZ: flush younger instructions HZ->>ID: stall/clear younger stages end WB->>WB: trap_commit = valid_W & exc_valid_W WB->>CSR: trap_valid/trap_cause/trap_pc/trap_addr/trap_addr_valid WB->>PC: wb_trap_redirect = 1, target = mtvec BASE WB->>HZ: flush_pipeline_onehot = 1111 CSR->>CSR: write mepc, mcause, mtval, update mstatus PC->>IF: fetch resumes at mtvec WB-->>IF: younger instructions flushed
Trap commit is strictly a WB action. The CSR regfile is updated atomically, and the hazard unit prevents younger instructions from committing out of order.

MRET Return Flow
