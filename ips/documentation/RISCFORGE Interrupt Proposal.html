1Where the project stands

RISCFORGE is the RV32IM_Zicsr 5-stage core in the SONIC-MCU SoC, headed for tape-out under the 1TOPS program. UART, SPI, I2C and GPIO enter as fast local interrupts (mip[19:16]) and Timer0 drives MTIP. A fixed if/else chain picks one interrupt. There is no PLIC and no CLINT. A design review on 24 Sep 2026 produced a phased fix plan. No RTL has changed yet.

2Reference work

Base paper: R. Balas et al., CV32RT: Enabling Fast Interrupt and Context Switching for RISC-V Microcontrollers, IEEE TVLSI 2024 [1]. The CLIC it integrates is the same PULP IP already in our repository.

What they did

  • Integrated the PULP CLIC into CV32E40P: levels, preemption, hardware vectoring
  • fastirq: second register bank, saved in the background; 6-cycle entry vs ≈33 with CLIC alone (Cortex-M4: 12)
  • CLIC area ≈176 GE per source, linear in source count; fastirq +10 % (GF 12 nm)

What they left open (our gap)

  • No PLIC in the comparison
  • Only large CLIC configurations, not ≤16-source MCUs
  • Best-case latency only: zero-wait memory, no dependence on the interrupted instruction
  • No area or timing sweep over design choices

3Goal and hypotheses

For a single-core, machine-mode MCU with 16 or fewer interrupt sources, what do a level arbiter, a PLIC and a minimal CLIC each cost in area, timing and latency on the same core?

H1The PLIC has the highest entry latency, because the handler must read a claim register and write a complete register over the bus.
H2At ≤16 sources, a level arbiter matches minimal-CLIC latency at lower area.
H3Every option is a small fraction of core area, so latency and verification risk should decide, not gate count.

Method. Same core, testbench, Genus library and constraints for all four. Area in NAND2 gate equivalents; slack and fmax on the interrupt path; entry latency best, worst and jitter; handler entry/exit instruction count. Sweep 4, 8 and 16 sources. The flow is checked by reproducing CV32RT's per-source CLIC slope. Every est. value above is a hypothesis to be replaced by measurement.

6Questions for reviewers

  1. In production MCUs, does interrupt-controller area ever drive the choice, or do latency and software support decide?
  2. For ≤16 sources, would you ship a CLIC subset or custom CSR arbitration?
  3. Is registering interrupt inputs at the core boundary (+1 cycle) standard practice?
