1. Rev B baseline versus the RTL on disk

Rev B describes a core with a six-source gateway, a depth-gated arbiter and a two-deep shadow stack, and its statement that mip[20] to mip[26] are provably zero. The files now in the repository describe a different interrupt design: thirteen sources, a software-managed priority threshold mintprio, and no shadow stack. Both are recorded below. Each Rev B check keeps its identifier; where its premise is absent on disk it is marked OPEN rather than rewritten, because the plan owner must decide whether to revise the plan or the RTL. Core pipeline and the interrupt hardware are described on the core interrupts page, the unit-level checks are in G4.12 unit verification, and the implemented source-to-interface map is in G3_IRQ_Architecture.html section 13.

The deployed path is entirely inside the core: peripheral pin, SoC fast_irq_i and timer_irq_i, irq_gateway, irq_arbiter, trap commit, csr_regfile. There is no CLIC, PLIC or CLINT. The CLIC exists as RTL instantiated nowhere. That absence is intentional: the project chose the direct interface over a PLIC or CLIC for speed and simplicity, which is an architecture rationale, not a measured advantage (decision). The minimum observable pulse width on a latched source is one clk_i cycle (D-73), so the injector must not generate narrower pulses; IC-1 asserts the floor. Rev B corrects its own Rev A table twice: Timer 0 compare was recorded as level, and the clear strobe was recorded as clearing all sources.

4. Arbiter, classes and the gate

The arbiter qualifies, rotates, selects, ranks and gates; each step is a separate check. The reference model computes the winner itself from stimulus and architectural CSR state, never from the DUT's grant, otherwise it would only compare two copies of the RTL.

Rev B's pre-emption rule is: allowed if and only if depth is zero or the incoming class is strictly greater than the current class, so at depth 2 nothing can pre-empt. On disk there is no depth. The gate is the threshold, which is software state:

mintprio is 2 bits at 0x7C0, resets to 0, and trap entry and MRET leave it untouched. Nesting is therefore a firmware protocol (raise the threshold, re-enable MIE, restore on exit), and the verification target becomes: no interrupt of class not exceeding the threshold is delivered, and software that follows the protocol sees correct context restoration. OPEN The plan does not yet contain those checks.

5. Shadow stack obligation

Rev B rejects a finding that asked for a synchronous exception inside the deepest handler to reach depth 3: a synchronous exception never pushes, and nothing can be pending at depth 2, so the scenario cannot be built. The real defect it found was that a push beyond depth 2 would be silently discarded with no cause, status bit or trap, which D-70 would cure with a three-deep stack and a defined exception (mcause 24, 10 edits in one file). IC-11 characterised today's discard using a recorded hierarchical force, with a depth-1 positive control so the depth-2 assertions are not vacuous; IC-12 specified the cure and was not executable.

On the file now in the repository none of this applies: csr_regfile.v holds one mepc, mcause and MPIE, written live at trap entry (csr_regfile.v:157-175). By my reading a second trap taken with MIE re-enabled overwrites the first context unless firmware saved it. OPEN IC-11, IC-12 and D-70 are retained as Rev B identifiers but have no object until the plan or the RTL is reconciled. Lock-step comparison does not cover nesting in either version.

Both gates feed the qualify step. The mie write mask is 32'hFFFF0888 (csr_regfile.v:187), covering bits [31:16], 11 and 7.

IC-14 crosses sources, the two gate registers and the two gate states, asserting the trap count as a number: 24 cases with six sources. If the same rule is applied to the thirteen on-disk sources it gives 52 (my arithmetic, not in Rev B). IC-15 is the clear-while-pending case: assert, hold, clear the gate, wait, restore, and count. Required: exactly one trap after restoration and none before, exactly one rising edge of the commit pulse, and MPIE constant at 1 for the mie-bit variant and 0 for the MIE variant. For level sources the retention holds only while the peripheral keeps its level, and the stimulus must say so (D-77). A source whose mie bit is cleared inside its handler must not be redelivered after MRET until the gate is restored.

7. mtvec mode

Both modes exist in the datapath, but the mtvec write preserves bits [1:0], so the mode field resets to 0 and can never become 1: vectored mode is dead code (csr_regfile.v:188, wb_trap_mret_commit_controller.v:98-100). Rev B calls this a defect: a WARL field always reading 0 is legal only if the vectored datapath does not exist. The measurable difference is the first retired PC of the handler: the base in direct mode, base plus four times cause in vectored mode for interrupts only.

8. Spurious interrupts

The behaviour is asymmetric and must be predicted, not reported as a defect: the same withdrawn request is delivered in one regime and cancelled in the other, and both are architecturally permitted (D-76).

CaseExpected behaviourCheck

S5 is the highest-consequence row: software that does not clear a level source first re-traps without bound.

9. Peripheral clear versus gateway clear

The required order is: the peripheral clears its own source, and the gateway strobe follows from trap commit. It is not a choice. The strobe is a one-hot decode of the commit and the cause (wb_trap_mret_commit_controller.v:81-92: bit 0 for cause 7, otherwise cause minus 15), issued when the interrupt is taken, so it always precedes the handler's first instruction; the peripheral clear is software and cannot. Figure 4 shows the sequence.

The obligation that survives is therefore about responsibility. For latched sources the handler needs a new rising edge, or for a compare, a re-arm. For level sources the handler must clear the peripheral before doing anything else, since a handler that reads status before writing it re-traps.

IC-8 grades the structural half (one-hot, one cycle, zero for exceptions). IC-20 grades the behavioural half and is the only check that can tell a double delivery from a lost interrupt, since both otherwise present as no finding.

10. The watchdog class

The AON watchdog is specified and not integrated. The block is real RTL instantiated nowhere; its host port is TileLink, not APB; soft_rst_ni is an external pin driven by nothing inside the SoC. D-75 assigns it class 2, level mode, lowest within class 2 (order ASSUMED, and a parameter of the arbiter model, not a constant). Because it is level-mode, the gateway cannot clear it and its own status must be cleared by software first. No IC-n is executable for it; IC-24 exists only so the row cannot vanish. On disk there is no cause 28 slot, so integration would widen the vectors as well.

11. Pre-emption and nesting

Rev B's contract: depth limit 2; pre-emption only by a strictly higher class or at depth 0; at depth 0 nothing is gated; irq_pending_o is zero at depth 2, so the maximum nesting is 2. 13. Configuration scope and limits

Every IC-n is graded in the integrated SoC configuration only. The core-only compliance tree uses a different interrupt design and has no gateway or arbiter, and the core-less configuration has no trap at all. A green IC-n reported in either is a harness defect, not a pass.

This page does not claim any interrupt reaches the sources Rev B lists as unrouted, does not claim lock-step grades nesting, and does not supply a third oracle for the timers (D-19: a cycle-accurate counter and compare model, raised to the peripheral owners).
