Core hazard unit, CSR register file and trap/MRET commit

How the 5-stage RV32IM_Zicsr core resolves data and control hazards, which CSRs it implements, and how a synchronous exception or MRET is committed at the write-back (WB) stage. Written from the RTL as it stands; for engineers reading or verifying the core.

1. Where these blocks sit

Pipeline stages are IF, ID, EX, MEM and WB, instantiated in riscv_core/rtl/top.v as Fetch, Decode, Execute, Memory and a write-back stage. Three blocks sit beside them. hazard_unit (instance Forwarding_block, top.v:589) produces forwarding selects, stalls and flushes. wb_trap_mret_commit_controller (top.v:517) turns an exception tag that reached WB into a redirect plus CSR updates. csr_regfile (top.v:553) holds the machine-mode CSRs. The design is machine-mode only: there is no privilege level other than M. EXISTS

Exceptions are precise by tagging: a stage that detects a fault sets exc_valid, exc_cause, exc_tval and exc_pc in its pipeline register, the tag travels with the instruction, side effects are suppressed on the way, and the trap is taken only when the tag is in WB (section 7).

Load-use timing. A load in EX with a dependent instruction in ID raises lwstall for one cycle: fetch and decode hold, EX receives a bubble. In the next cycle the load is in MEM and the consumer is still in ID; it enters EX when the load is in WB and takes ResultW through select 01. One bubble results. EXISTS

Other observations, all EXISTS: there is no StallW; MEM/WB holds on core_stall_gated, which is the LSU stall with misaligned accesses masked out (memory_cycle.v:186,193). Instruction-memory wait is added inside fetch (StallF | imem_stall_raw, fetch_cycle.v:135,260) and is not part of the hazard unit.

4. DEF-001 and the mem_stall_i gating

Defect DEF-001 is "load-use flush inserted during MMIO memory stall drops loads" (Verification/status/defects.csv). Mechanism: during a multi-cycle MMIO access mem_stall_i holds IF, ID, EX and MEM (Figure 2). If the instruction held in EX is a load whose consumer is in ID, lwstall is also true. Without gating, FlushE would be asserted, and because flush outranks hold in ID/EX (Figure 3) the held load would be replaced by a bubble and lost. EXISTS

The current file gates the three data-hazard terms: lwstall, csr_gpr_stall and csr_stall are each ANDed with ~mem_stall_i in FlushE (hazard_unit.v:192, rationale at :189-191). The stall outputs are not gated, so the hazard is still honoured: StallF/StallD hold the consumer in ID for as long as the memory stall lasts, and the bubble is inserted on the first cycle after it ends.

Status. DEF-001 is FIXED-UNVERIFIED in PHASE_STATUS.md and defects.csv: the fix is in the file, but no directed regression that fails on the old RTL exists yet (action ACT-010). This page documents the equation, not a verification result. Branch and exception terms of FlushE (PCSrcE, exc_inflight_M, wb_redirect, stallMUL) are deliberately ungated; top.v additionally ORs irq_flush_frontend into FlushD and FlushE with no mem_stall gate. That last path is discussed on core_interrupts.html as an OPEN point.

Rev B section 13.5 describes a two-deep stack of mepc, mcause, mpie and class at csr_regfile.v:84-88, pushed on interrupts and dropped silently at depth 2. That description matches an earlier revision of the file: lines 84-88 of the current file are part of the mintprio comment, and the header of top.v (lines 7-8) names "software-managed interrupt nesting" through mintprio. Priority. The rule along the pipeline is that the first tag wins. A tag set in ID is carried unchanged through EX and MEM (execute_cycle.v:466-478, memory_cycle.v:144-147). In EX a new misaligned-target exception cannot coexist with an inbound tag because branch_taken_raw includes ~exc_valid_E (:283). An interrupt is accepted only when no exception is already tagged (irq_accept_E = valid_E & irq_pending_i & ~new_exc_valid_E & ~exc_valid_E, :459). In MEM an inbound tag beats a local fault. Within MEM a misaligned access beats an access fault (:134-139). Older instructions reach WB first, so program order decides between different instructions. EXISTS

A tagged instruction has its register write, memory write and CSR write enables cleared when it leaves EX (execute_cycle.v:411-420) and its memory request gated off in MEM (memory_cycle.v:179-180). fetch_cycle carries an exception tag channel into ID; no source that sets it (an instruction-fetch fault) was found in the files read. 7. Trap commit at WB

In WB, trap_commit = valid_W & exc_valid_W (wb_trap_mret_commit_controller.v:64). One commit does five things, shown in Figure 5.

  • Redirect: wb_trap_redirect_o = trap_commit | mret_commit; the fetch stage uses trap_target as the next PC when it is high (fetch_cycle.v:119).
  • Target: direct mode (and all exceptions) use {mtvec[31:2], 2'b00}. If mtvec[1:0] == 01 and the trap is an interrupt the target is base + 4 x cause (:98-103). Because the CSR never stores 01 in the mode field (section 5), the vectored branch is unreachable today. EXISTS as logic, OPEN as reachable behaviour.
  • CSR capture on trap_valid_o: mepc from exc_pc_W; mcause from the flag and cause; mtval from exc_tval_W only for exceptions (trap_addr_valid_o is low for interrupts, so mtval becomes 0); MPIE gets MIE, MIE clears, MPP becomes 11 (csr_regfile.v:159-167).
  • Flush: flush_pipeline_onehot_o is 1111 (:106), which together with wb_redirect clears IF/ID, ID/EX, EX/MEM and MEM/WB and releases all stalls.
  • Interrupt feedback: for an interrupt commit, wb_commit_irq_o pulses and clear_gateway_o clears the gateway bit (cause 7 to bit 0; causes 16 to 27 to bits 1 to 12, :78-92).

8. MRET commit

MRET is decoded in ID (is_mret, decode_cycle.v:142,189), carried as is_mret_r through every stage register, and committed at WB when valid_W & is_mret_W & ~exc_valid_W (wb_trap_mret_commit_controller.v:65). Figure 6 gives the flow. EXISTS
