02 · Shared failure mechanism · EXC-002

The trap fires, but younger work escapes

01 · ISSUEOlder instruction faultsA younger DIV/REM reaches the M engine before or on the flush edge.

03 · COMPLETEOld result arrivesm_valid_out overrides current rd, result and write enable without an ownership check.
04 · SIDE EFFECTHandler store carries itStore PC/control metadata and the stale M destination/result reach WB together.
High-confidence DUT defect inference

The wrong-path instruction’s destination and exact arithmetic result match the extra raw WB update in every case. All PC/word rows align with Spike. This supports a precise-exception failure, rather than a CSV row shift.

The logs show write intent. Historical post-edge register readback and internal issue/done/kill waveforms are unavailable. Store-address corruption is also possible through the result mux, but is not measured by these logs.

Trigger condition: younger M work is accepted, survives an older exception flush, then completes while an unrelated valid instruction can capture it. Misalignment alone is insufficient.

04 · Known illegal-decode defect · DEC-001

Recognized opcode does not mean legal instruction

Open. Illegal seed 22 executes 0x460446b3 at 0x800002d8. Its opcode 0x33 is accepted, but funct7 0x23 with funct3 4 is not a valid RV32IM operation.

Spike

Cause 2, mepc = 0x800002d8; no a3 write. After the handler, dependent add produces a1 = 10.

RTL

Accepts it as XOR s0,x0, writes a3 = 0x53a033ed; dependent add gives a1 = 0x53a033ee.

opcode_check.v:23–43 receives only the major opcode; ALU_Decoder.v:116–118 selects XOR without full funct7 legality. This is present in the current local core too.

legal_xor = opcode_is_OP && funct3_is_100 && funct7_is_0000000;
legal_instruction = legal_xor || legal_other_supported_pattern || ...;
illegal_instruction = !legal_instruction;

AND fields within each legal pattern, OR the patterns. Use full-instruction, format-specific rules for immediate shifts, SYSTEM and the declared extensions; separately validate CSR access. A 131,072-combination field sweep is exhaustive only over opcode/funct3/funct7, not every instruction bit or architectural state.

Seed 22’s last-observed register values eventually converge. Its earlier corrupt writes would be missed by final-state-only checking. Prior evidence: artifacts/riscv_dv_seed22_inspection_20261103_030831/inspection.md.

05 · Source applicability and proposed closure

The current local core needs its own reproduction

The remote project snapshot has no M-unit trap cancellation. The local core is different: it has divider abort, but execute_cycle.v:297 drives it only from irq_accept_E & stallMUL. Synchronous exception flush is absent. Local issue and completion ownership checks remain insufficient in the inspected wiring.

Source evidence, not a local simulation result

Local: execute_cycle.v:293,297,310,329–331,411–424.
Remote preserved snapshot: execute_cycle.v:286,289–326,400–415; rv32m_unit.v; rv32m_div.v.
The local and remote Execute files have different SHA256 values; both are preserved.

  1. DEC-001: implement a full-encoding legality decision with an independent expected model; verify trap cause/PC and suppression of all faulting side effects.
  2. EXC-002: qualify issue, cancel/invalidate killed transactions, and accept completion only for its live owner. Preserve transaction metadata; give kill priority over completion. Gating new starts alone does not remove already-issued stale work.
  3. Directed closure: reproduce the three older-trap + younger DIV/REM sequences. Exercise same-edge issue/flush and kill/completion, plus flush during computation. Check GPR, CSR and memory address/data/strobes, trap CSRs and return behavior.
  4. Regression closure: pin RTL, harness, tool/configuration and generated assembly/binary; rerun failed seeds and relevant regressions. No fix or closure simulation has been performed.

The GPR-change comparator skips stores, branches and unchanged writes. A single extra update shifts its later pairings, explaining the 23/23/24 mismatch counts. It does not establish full retirement, CSR or memory equivalence. The trace logger infers instruction association from PC tracking; it is not a complete retirement interface.

Spike and Cadence run independently and are compared offline. A tohost pass establishes program completion under the testbench rule, not architectural equivalence. The BARE configuration does not validate virtual-memory translation despite the “MMU stress” test name.
