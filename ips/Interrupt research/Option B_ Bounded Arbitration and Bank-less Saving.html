Stage 1 · Baseline: what we have

Approach and corner-case findings

  • Sources feed mip live; a fixed priority picks the highest cause, then mintprio and MIE gate it.
  • Two problems to attack: same-priority starvation (a fast source can keep a lower-numbered peer waiting) and software save cost S.
  • Corner cases already present: a CSR write to mstatus/mie/mintprio still in MEM/WB while EX accepts (the interrupt could be taken after code disabled it; verify with an assertion); an older exception beats the interrupt; a multi-cycle op blocks acceptance.
Measure first (week 1): L0 (IRQ → first handler instruction) · S (software save cost) · per-source worst-case wait under a storm of a same-priority peer · baseline flop and GE counts.

Stage 2 · M1: bounded hybrid priority / round-robin arbiter

Approach after corner-case analysis

  • Fixed class per source (2 bits in a CSR table); round-robin inside a class. Higher classes still preempt, so urgent sources keep low latency.
  • The pointer moves at commit, not at decision or accept, so fairness state only changes when a trap is really taken.
  • Grant id is captured at the accept cycle, so mcause always names the interrupt actually taken.

Quantifiable outcome (targets):
  • Worst-case same-class wait: unbounded under fixed priority → (n − 1) services, proven for n sources.
  • Arbiter area per source: est. a few tens of GE, against about 176 GE per source for the CLIC configuration registers reported in [1] (confirm by synthesis).
  • Arbitration adds no cycles to entry (combinational in the existing gating path); confirm in timing.

Stage 3 · M2: how bank-less, mask-guided saving happens

How it happens, step by step

  1. Commit: at WB every older instruction has retired, so the register file is the exact interrupted state. The idle WB write port lowers sp by 4N (rounded to 16 bytes).
  2. Load the mask: pending ← mask[source]. All-ones is the safe default.
  3. Handler starts immediately at the vector, about the same cycle count as any trap entry.
  4. Background sweep: the engine reads one pending register per granted SRAM slot through an extra read port and stores it to its frame slot.
  5. Demand first: if the handler is about to write a pending register, the writer stalls a cycle or two while that register is saved next.
  6. No bank needed: the register file itself keeps the interrupted values until the handler overwrites them, and the interlock guarantees nothing is overwritten before it is saved.
  7. Exit: software restores the masked registers and executes mret, which waits until pending is empty.

Quantifiable outcome (targets):
  • Entry to first C-callable instruction: L0 + S (about 33 cycles for a software baseline in [1]) → L0 + small; at or near the 12-cycle Cortex-M4 reference in [1].
  • Stack traffic per entry: 16 words → N words, for example 5 for a short GPIO handler (illustrative), which also shortens the hazard window.
  • State: est. 170 flops for 8 sources with masks (about 40 without), against a 512-flop bank; confirm by synthesis.
  • Proofs: no register overwritten while pending; each stacked word equals its value at trap entry; save completion within a stated bound; mask soundness by Spike co-simulation.
