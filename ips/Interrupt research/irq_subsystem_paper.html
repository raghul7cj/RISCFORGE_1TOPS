1 · Introduction and motivation

The RISCFORGE core takes interrupts straight from peripheral wires into mip and picks a winner with a fixed-priority chain. That is fast but has four weaknesses (Fig. 2): transient pulses can be lost, a busy high-ranked source can starve lower ones and the system tick, the threshold compares cause numbers instead of priorities, and a divide in EX can delay acceptance. We propose a small core-local front end that fixes these in standard CSR space, with no bus traffic and no compiler changes.

Fig. 3 — Proposed path. Solid blocks in the top row are new; dashed arrows are commit-time feedback (auto-clear and pointer rotation). The pointer moves at commit so a cancelled accept never disturbs fairness.

How the solution works

  • Gateway: a rising edge sets pend_q, so a pulse survives while MIE is clear or another ISR runs. Commit clears the bit for the captured id, and a new pulse in the same cycle wins over the clear.
  • Classes and round-robin: urgent sources sit in a higher class and still win. Inside a class the pointer moves past the last served source, so no peer is starved.
  • Levels: an interrupt preempts only if its class is above the current level; hardware pushes on entry and pops on mret. Depth is levels − 1 backups, so 4 classes need 3.
  • Toolchain: the standard vectored mtvec and mret are unchanged. Handlers still save mepc before re-enabling MIE for nesting.

7 · Evaluation and validation

  • Formal (SymbiYosys): pulse never lost, no lower class granted before a waiting higher class, same-class wait at most n − 1 services, auto-clear only for the taken id. Baseline gives a counterexample; the new design proves it.
  • Metrics: flops and GE per feature, worst-case wait per source, acceptance latency (with the abortable divider: about 40 → 6, to confirm), RISCOF still passing.
  • Venues: 4–5 page letter or conference first; TCAS-II only with the divider bound.
