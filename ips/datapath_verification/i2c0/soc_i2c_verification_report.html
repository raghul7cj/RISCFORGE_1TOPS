2. SoC Architecture & System Interconnect

The RISCFORGE 1TOPS SoC integrates a high-performance memory and bus interconnect architecture. The RV32IM core accesses Instruction SRAM directly via a fetch demux and routes load/store accesses through hybrid_mem_interface: direct accesses map to DSRAM, while MMIO ranges (0x4000_0000 - 0x4FFF_FFFF) cross the 2x3 AXI4-Lite crossbar to the APB bridge.

4. Software Toolchain Dataflow

The verification binary is built with the GNU RISC-V Toolchain (riscv64-unknown-elf-gcc) targeting rv32im_zicsr. The custom Python linker post-processor (elf_to_hex.py) parses section headers and partitions the ELF into separate word-addressed hex images for ISRAM (0x0001_0000) and DSRAM (0x0002_0000).

[crt0.S + i2c_smoke_test.c + link.ld] → (GCC -O2) → app.elf → (elf_to_hex.py) → [imem.hex (432 words) + dmem.hex (2308 words)]

5. Detailed Test Execution & Results

Test 1: Single-Byte EEPROM Write (Address 0x10 ← 0xA5)

The RV32IM core programs the I2C Master registers to issue a START condition, sends the 7-bit slave device address 0x50 with Write bit (0xA0), transmits the memory word offset 0x10, writes byte 0xA5, and terminates with a STOP condition. The AT24C02 slave asserts ACK across all phases.

Test 2: EEPROM Random Read & Data Integrity Check (Address 0x10 → 0xA5)

The core executes a combined-format random read: dummy write phase to set the internal memory word address pointer to 0x10, followed by a Repeated START with Read bit (0xA1). The slave outputs the byte stored at 0x10. The master responds with NACK and STOP, and compares the received value against 0xA5.

Test 3: Multi-Location Non-Contiguous Verification

Validates multiple memory address offsets (0x20 ← 0x5A, 0x30 ← 0x3C). After allowing the internal write cycle to commit, the core executes random reads from both locations and verifies that the retrieved data exactly matches expectations.
