1Executive summary

The RISCFORGE SoC integrates 5 active peripheral interrupt sources: UART, SPI, I2C, the system timer (MTIP), and GPIO pin interrupts. As originally implemented, the subsystem directly wires peripheral interrupt lines into the core's mip register and evaluates them with a fixed combinational priority tree in top.v.

Detailed verification and RTL auditing uncovered two critical architectural bugs and one starvation vulnerability:

  • Pulse Interrupt Loss: SPI transmit/receive events and GPIO edge transitions produce single-cycle or brief pulses. If an interrupt arrives while the core is inside another ISR or while interrupts are globally disabled (mstatus.MIE = 0), the pulse vanishes before the core can service it, leading to silent packet loss and system lockups.
  • Inverted Priority Comparison: The current priority chain in top.v compares interrupt cause numbers rather than priority weights, causing low-priority interrupts to preempt high-priority ones, and scheduling the system timer (cause 7) ahead of external interrupts (cause 11), violating the RISC-V Privileged Architecture Specification.
  • Starvation Under Contention: Fixed priority ordering creates an unfair bias where streaming peripherals (such as UART or SPI) can indefinitely starve lower-ranked peripherals (like I2C).

The Solution & Silicon Cost: A lightweight, two-stage hardware subsystem consisting of irq_gateway (per-bit pulse-to-level capture with hardware auto-clearing) and irq_arbiter (4 programmable priority levels with round-robin tie-breaking across equal-priority channels). Across all phases (A + B1 + B2), the complete design introduces approximately 110 flip-flops and 1.1 to 1.5 kGE (around 5–7% of the RV32IM core logic, and well under 0.1% of the total SoC with memory), operating with zero added interrupt cycle latency.

2Current implementation

The RISCFORGE core implements the RV32IM instruction set with the Zicsr machine-mode privileged architecture. The core exposes standard machine-mode interrupt lines as well as 16 Fast Local Interrupt lines (FLI0 through FLI15), mapped directly to causes 16 through 31.

3Findings & defect analysis

F1 — Pulse interrupts are lost

When an SPI transfer completes or an external pin triggers a GPIO interrupt, the respective peripheral asserts a brief pulse (1 to 2 cycles). If the core is currently executing an ISR (where global mstatus.MIE = 0), or if a higher-priority interrupt is being evaluated, the pulse drops back to zero before the core commits the trap. Because mip merely mirrors the raw input wire, the pending bit vanishes into thin air.

F2 / F3 — Priority order defect

The RISC-V Privileged Specification specifies the default priority order: MEIP (11) > MTIP (7) > MSIP (3) > Fast Local Interrupts (16–31).

The current implementation contains two bugs: first, it checks MTIP before MEIP. Second, within the fast local interrupts, it uses inverted numerical comparisons that treat cause 31 as higher priority than cause 16.

F4 & F5 — Thresholding & starvation

The custom CSR mintprio was intended to set a minimum priority threshold. However, it currently masks based on the numerical cause index, meaning setting a threshold to allow timer interrupts unintentionally masks out all peripheral interrupts.

Furthermore, under sustained UART or SPI traffic, lower-priority peripherals like I2C experience indefinite starvation.

4Options evaluated

To establish the cleanest, most efficient interrupt architecture for the RISCFORGE microcontroller, four major architectural options were evaluated against silicon area, latency, software effort, core intrusion, and verification risk.

Why area does not drive this decision: Every option except D represents a modest portion of an RV32IM 5-stage core (~18–22 kGE). The deciding factors are verification risk, spec conformance (RISCOF and Sail compliance suites must stay 100% clean), and latency determinism.

Policies considered and rejected

  • Weighted round-robin (per-peripheral weights): Requires a credit counter per source (4–8 flip-flops each) plus reload state machines. Interrupts are discrete events rather than continuous streaming packet flows; weights do not tighten latency bounds and make verification history-dependent.
  • Aging (priority boost while waiting): Latency becomes heavily dependent on arrival histories, making formal bounds difficult to write in SVA and prove in JasperGold. It also masks root-cause software bugs (such as un-serviced peripheral flags).
  • Full CLIC for current tapeout: While CLIC is the ultimate long-term standard for RISC-V microcontrollers, it replaces standard trap vectoring with table lookups across the data bus and mandates non-ratified CSR extensions. Phase B achieves comparable 4-level preemption and starvation freedom at a fraction of the RTL and verification cost.

5Is a PLIC needed for MCU scope?

A full Platform-Level Interrupt Controller (PLIC) is the standard RISC-V solution for multi-core application processors with dozens or hundreds of interrupt lines. However, for a single-hart microcontroller with 5 to 16 peripheral sources, a PLIC introduces severe engineering drawbacks:

Silicon Gate Count
PLIC: 3,000–5,000 GE · Proposed: 1,100–1,500 GE (3x smaller)
ISR Entry Overhead
PLIC: 18–26 bus cycles · Proposed: ≤ 4 core cycles (6x faster)
Bus Contention
PLIC: Competes on APB bus · Proposed: Direct CSR execution
Software Footprint
PLIC: Claim/complete MMIO read/write · Proposed: Direct Vector

The proposed custom CSR approach maps interrupt arbitration directly into Machine-mode CSR space (0x7C0–0x7C2). This gives the programmer complete 4-level preemption control and dynamic priority assignment with zero bus transaction overhead.

6Proposed architecture

The revised interrupt subsystem introduces two dedicated hardware modules positioned between the peripherals and the execution pipeline: irq_gateway and irq_arbiter.

Subsystem A: Hardware Pulse Gateway (irq_gateway)

The gateway guarantees that transient interrupt pulses are never dropped. For every bit configured in edge mode, a positive transition on the input sets an internal latch flip-flop. The latch remains asserted until explicitly cleared by software or automatically cleared when the CPU enters the corresponding interrupt trap.

Signal name Width Direction Clock domain Microarchitectural function
clk_i 1 Input Core Clock System clock (50 MHz)
rst_n_i 1 Input Asynchronous Active-low master reset
irq_raw_i 32 Input Peripheral Raw interrupt lines: {FLI[15:0], 4'b0, MEIP, 3'b0, MTIP, 7'b0}
edge_sel_i 32 Input Static/CSR Mode mask: 1 = pulse edge-capture, 0 = level pass-through
clear_i 32 Input Core Pipeline 1-cycle auto-clear strobe from trap controller upon committing ISR
irq_pend_o 32 Output Core Clock Synchronized pending interrupt vector driving core mip

Subsystem B: Custom CSR Interface (CSRs 0x7C0–0x7C2)

Control and priority configuration are managed via three custom machine-mode CSRs residing in the standard user-definable range (0x7C0–0x7FF), ensuring zero conflict with standard RISC-V extensions.

mintprio (0x7C0)

Priority Threshold
Read / Write Reset: 0x00

Controls execution priority thresholds for preemption filtering:

  • [2:0] CUR: Current CPU priority threshold (0–3). Only interrupts with level > CUR can interrupt.
  • [10:8] PREV: Hardware stack saving the prior threshold level during nested preemption.

mintctl (0x7C2)

Arbitration Control
Read / Write Reset: 0x01

Enables arbitration policies and hardware features:

  • [0] RR_EN: Round-robin enable. When set, equal-priority channels rotate to prevent starvation.
  • [1] NEST_EN: Hardware preemption nesting enable. Automatically saves/restores priority levels.

Subsystem C: Priority Arbiter (irq_arbiter)

The arbiter is a purely combinational datapath that evaluates all active interrupts (mip & mie) every clock cycle, guaranteeing zero latency bubbles.

4-Stage Combinational Decision Logic:

  1. Threshold Gating: Candidates are masked out if their assigned level ≤ cur_lvl_i.
  2. Level Partitioning: Remaining candidates are sorted into 4 priority buckets (Level 3 down to Level 0).
  3. Priority Resolution: The highest non-empty priority bucket wins immediately.
  4. Intra-Level Arbitration: If multiple peripherals share the winning level, round-robin rotating priority selects the winner based on token pointer rr_ptr_i.

Subsystem D: Preemptive Hardware Nesting

7Phased fix plan

To mitigate risk and ensure immediate tapeout correctness, the implementation is partitioned into three distinct phases:

Phase A: Correctness Fix

Mandatory · Drop 1
RTL Bugfix top.v / csr_regfile.v

Resolves critical functional defects without changing software contracts:

  • Instantiate irq_gateway with static edge mask 0x0005_0080 (SPI, GPIO, Timer).
  • Correct the priority chain in top.v: MEIP > MTIP > MSIP > FLI0..FLI15.
  • Implement 1-cycle auto-clear on trap commit for pulse sources.

Phase B1: 4-Level Arbiter & RR

Recommended · Drop 2
Feature Complete CSRs 0x7C1–0x7C2

Introduces runtime priority programmability and anti-starvation:

  • Instantiate irq_arbiter in core datapath.
  • Add CSR mintlvl (0x7C1) for 2-bit per-channel priority assignment.
  • Add CSR mintctl (0x7C2) with rotating irq_rr_ptr token.

Standard cell library gate count & flop analysis

Sequential vs. Combinational Area Realities:

  • In standard CMOS cell libraries (e.g. TSMC 28nm / GF 12nm / SkyWater 130nm), a single D-flip-flop with reset (DFFR / SDFFRE) occupies 4.5 to 7.0 NAND2 Gate Equivalents (GE).
  • The total sequential flip-flop count across A + B1 + B2 is ~107 to 110 flops, which alone represents $approx 107 imes 5.5 = mathbf{590 ext{ to } 750 ext{ GE}}$.
  • The remaining ~500 to 750 GE comprises combinational priority logic: 32-bit edge detectors, threshold comparators, 4-level parallel encoders, and the round-robin rotating token arbiter.
  • Total cumulative subsystem area is 1.1 to 1.5 kGE (~1,100 to 1,500 GE).

Core Area Impact & Offsets:

  • The RV32IM 5-stage core (with hardware M-extension multiplier/divider, register file, and CSR file) measures approximately 18,000 to 22,000 GE (18–22 kGE).
  • The entire interrupt subsystem upgrade represents approximately 5.5% to 7.5% of the active core logic, and under 0.1% of the total chip area.
  • In Phase B1, the legacy mintprio_r register shrinks from 32 flops to 6 active bits, reclaiming ~26 flops (~150 GE) which partially offsets the B1 arbiter cost.

Timing Closure Note: The arbiter sits on the mip → irq_pending → irq_accept_E → FlushD critical path. If static timing analysis (e.g. Cadence Genus or Synopsys PrimeTime) shows negative slack at the 50 MHz target clock, setting IRQ_ARB_REG = 1 registers irq_pending/irq_id, adding one pipeline cycle while ensuring robust timing closure across all PVT corners.

9Verification plan

The verification strategy combines directed assembly testcases in the SystemVerilog testbench with formal property verification (FPV) using Cadence JasperGold.

Test ID Test description Stimulus / Verification criteria Signoff status
IRQ01 SPI pulse capture while in UART ISR Assert 1-cycle SPI pulse while core executes UART handler; verify SPI pending bit latched in gateway. Passed TB1
IRQ02 Pulse capture during global disable (MIE=0) Trigger GPIO and SPI pulses while mstatus.MIE=0; verify trap fires immediately after MIE is re-enabled. Passed TB1
IRQ03 Auto-clear verification Verify gateway pending flip-flop clears automatically upon trap commit without software intervention. Passed TB1
IRQ04 Priority spec compliance (MEIP vs MTIP) Simultaneous MEIP and MTIP assertion; verify MEIP vectors first per RISC-V specification. Passed TB1
IRQ05 4-Level preemption & nesting Level 1 ISR interrupted by Level 3 ISR; Level 2 ISR queued; verify nested stack and return sequence. Phase B2
IRQ06 Round-robin anti-starvation Continuous simultaneous requests on SPI and I2C at Level 1; verify strict alternating grants (1:1 ratio). Phase B1

Formal Verification Properties (JasperGold FPV)

  • Safety Property 1 (Pulse Latch Guarantee): Any 1-cycle pulse on irq_raw_i[k] when edge_sel_i[k]=1 results in irq_pend_o[k]=1 until clear_i[k]=1.
  • Safety Property 2 (Priority Soundness): If interrupt A has a higher programmed level than interrupt B, B is never granted while A is eligible.
  • Liveness Property (No Starvation): Under continuous requests from multiple peripherals at the same level, every peripheral is guaranteed a grant within at most N arbitrations.

Nested ISR execution stack layout

For preemptible interrupts (NEST_EN = 1), the ISR wrapper dynamically re-enables mstatus.MIE = 1 while the hardware threshold register protects against equal or lower-priority preemption.

Stack Frame Footprint: 80 bytes reserved per nested frame (saving ra, temporary registers t0–t6, and argument registers a0–a7). Context switch overhead is exactly 24 cycles on entry and 22 cycles on return.
